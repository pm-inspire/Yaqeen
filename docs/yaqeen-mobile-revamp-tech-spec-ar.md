## 🗺️ هيكل التطبيق

### 🧭 تسلسل المحتوى (Content Hierarchy)
يعتمد التطبيق على تسلسل ثابت للمحتوى التعليمي:

**دورة (Course) → فترة (Period) → معلم (Teacher) → وحدة (Unit) → درس (Lesson)**

### 🧱 تعريفات مختصرة (مصطلحات)
| المصطلح | التعريف | أمثلة على البيانات |
|---|---|---|
| **الدورة** | حزمة تعليمية مرتبطة بمرحلة/صف/مادة | اسم الدورة، صورة، وصف، تقييم |
| **الفترة** | باقة/مدة اشتراك للدورة | مدة، سعر، حالة الاشتراك |
| **المعلم** | مقدم الشرح/المحتوى | الاسم، التقييم، السيرة |
| **الوحدة** | تجميع دروس ضمن محور | اسم الوحدة، عدد الدروس |
| **الدرس** | أصغر وحدة تعلم | عنوان، فيديو/ملفات، أسئلة |

### 🧩 خريطة التنقل عالية المستوى
| القسم | يدخل منه المستخدم | مخرجات متوقعة |
|---|---|---|
| **الرئيسية** | اكتشاف الدورات + البحث + التصفية | فتح تفاصيل الدورة / نتائج البحث |
| **تفاصيل الدورة** | قرار الاشتراك/المتابعة | اشتراك/مشاركة/مفضلة/تقييم |
| **شروحاتي** | متابعة المحتوى الذي تم شرحه/حفظه | فتح تفاصيل الشرح |
| **ساحات النقاش** | أسئلة/نقاشات | فتح منشور + التعليقات |
| **المحادثة** | تواصل (حسب سياسة التطبيق) | محادثات + رسائل |
| **المزيد** | الحساب/الطلبات/المساعدة/عنّا/الخروج | إعدادات وخدمات داعمة |

## 🎯 أهداف التحديث (Business + UX)

### ✅ أهداف قابلة للقياس
- **رفع معدل التحويل للاشتراك** عبر تحسين رحلة غير المشتركين (Course Details - Non-Subscribers).
- **تسريع الوصول للمحتوى** عبر بحث/فلترة/ترتيب أكثر وضوحًا.
- **تقليل الانسحاب** عبر حالات تحميل/أخطاء/انقطاع شبكة واضحة، ورسائل موجهة.
- **زيادة الاحتفاظ** عبر المفضلة، شروحاتي، وإشعارات داخلية (In-app prompts) عند الحاجة.

### 💎 وعود قيمة للمستخدم
- العثور على الدورة المناسبة بسرعة.
- فهم واضح لما سيحصل عليه قبل الاشتراك.
- تجربة مشاهدة/شرح مستقرة ومريحة على الهاتف.
- تفاعل مجتمعي (نقاش/تعليقات) منظم وسهل المتابعة.

## 📐 معايير عامة للتجربة والتصميم (Design & UX System)

### 🌍 دعم العربية وواجهة RTL
- واجهة **RTL بالكامل** مع استثناءات للروابط/الأرقام/الأكواد عند الحاجة.
- توحيد الأرقام (عربية/إنجليزية) وفق قرار المنتج، مع دعم العملتين/الأسعار بصيغة ثابتة.

### ♿️ الوصولية (Accessibility)
- تباين ألوان مناسب، أحجام خط قابلة للتكبير.
- تسميات واضحة لعناصر الأزرار (Accessibility labels) خاصة للأيقونات.
- دعم قارئ الشاشة في العناصر التفاعلية الأساسية.

### 🧠 مبادئ التفاعل
- **حالة تحميل**: Skeletons بدل شاشات فارغة.
- **حالة فارغة**: نص + سبب + إجراء مقترح (CTA).
- **حالة خطأ**: رسالة مفهومة + زر إعادة المحاولة.
- **حالة دون اتصال**: شريط تنبيه + وضع قراءة/عرض إن أمكن.

## 1) 🏠 الرئيسية (Home)

- **الهدف**: تمكين المستخدم من اكتشاف الدورات بسرعة، والدخول للبحث والفلترة.
- **المكونات الأساسية**:
  - شريط علوي: شعار/اسم التطبيق + أيقونة (بحث) + أيقونة (مفضلة/حساب حسب القرار).
  - شريط اختيار المرحلة/الصف (CTA يفتح شاشة تحديد المرحلة والصف).
  - أقسام دورات: (مقترحة/الأكثر مشاهدة/حسب المرحلة…).
  - بطاقات دورة: صورة + عنوان + تقييم + زر مفضلة + حالة الاشتراك (إن وجدت).
- **التفاعلات**:
  - فتح بطاقة دورة ⟵ ينتقل إلى (تفاصيل الدورة).
  - فتح البحث ⟵ ينتقل إلى (نتائج البحث) بعد إدخال الاستعلام.
  - فتح الفلترة/الترتيب ⟵ شاشات (Sort By) و(Search Filter).
- **الحالات**:
  - تحميل: Skeleton لقائمة البطاقات.
  - فارغ: “لا توجد دورات متاحة لهذه المرحلة/الصف” + زر تعديل الاختيار.
  - خطأ: رسالة + زر “إعادة المحاولة”.
- **البيانات المطلوبة**:
  - `stage_id`, `grade_id`
  - قائمة `courses[]` (id, title, cover, rating, is_favorited, subscriber_state)
- **التتبع**: `home_view`, `course_view` (عند فتح التفاصيل), `favorite_toggle`.
- **معايير القبول**:
  - تغيير المرحلة/الصف يعيد تحميل الدورات ويحدّث العناوين.
  - الضغط على بطاقة دورة يفتح التفاصيل الصحيحة.

## 2) 🎓 تحديد المرحلة والصف الدراسي (Select Educational Stage & Grade)

- **الهدف**: ضبط السياق التعليمي لتخصيص المحتوى.
- **المكونات الأساسية**:
  - قائمة مراحل (Radio/Chips).
  - قائمة صفوف تعتمد على المرحلة المختارة.
  - زر “تأكيد”.
- **التفاعلات**:
  - اختيار مرحلة يحدّث الصفوف مباشرة.
  - زر تأكيد يحفظ التفضيل ويعود للشاشة السابقة.
- **الحالات**:
  - تحميل الصفوف عند تغيير المرحلة.
  - خطأ: فشل تحميل الصفوف + “إعادة المحاولة”.
- **التحقق والقيود**:
  - لا يمكن التأكيد دون اختيار المرحلة والصف.
- **البيانات المطلوبة**:
  - `stages[]`, `grades[]`
  - تخزين محلي: `selected_stage`, `selected_grade`
- **التتبع**: `stage_grade_select` (مقترح).
- **معايير القبول**:
  - بعد التأكيد تظهر المرحلة/الصف في الرئيسية.

---

## 3) 🔀 ترتيب حسب (Sort By)

- **الهدف**: تمكين المستخدم من إعادة ترتيب نتائج العرض (الرئيسية/نتائج البحث).
- **المكونات الأساسية**:
  - خيارات ترتيب (Radio):
    - الأحدث
    - الأعلى تقييمًا
    - الأكثر مشاهدة
    - السعر (إن كان متاحًا)
  - زر “تطبيق”.
- **التفاعلات**:
  - اختيار خيار ثم تطبيق يعيد تحميل القائمة وفق الترتيب.
- **الحالات**:
  - تعطيل زر التطبيق حتى اختيار خيار.
- **البيانات المطلوبة**:
  - `sort_key`
- **التتبع**: `sort_apply` (مقترح).
- **معايير القبول**:
  - يتم تطبيق الترتيب دون فقدان الفلاتر الحالية.

---

## 4) 🧰 فلتر بحث (Search Filter)

- **الهدف**: تضييق نتائج البحث/التصفح حسب معايير واضحة.
- **المكونات الأساسية** (حسب بيانات المنتج المتاحة):
  - المرحلة/الصف (للعرض أو للتعديل).
  - المادة/التصنيف (إن وجد).
  - المعلم (إن وجد).
  - مستوى الصعوبة/المدة/السعر (اختياري).
  - زر “تطبيق” + زر “إعادة تعيين”.
- **التفاعلات**:
  - تطبيق الفلاتر يعود لنتائج البحث/القائمة.
  - إعادة تعيين تمسح الحقول وتعيد الافتراضي.
- **الحالات**:
  - تحميل القوائم المساعدة (teachers/categories).
- **التحقق والقيود**:
  - منع توليفات غير منطقية (مثلاً: صف لا ينتمي لمرحلة).
- **البيانات المطلوبة**:
  - `filters` (key/value)
- **التتبع**: `filter_apply`, `filter_reset` (مقترح).
- **معايير القبول**:
  - مؤشر عددي يظهر عدد الفلاتر المفعّلة (إن كان ضمن التصميم).

## 5) 📘 تفاصيل الدورة (لغير المشتركين) (Course Details - Non-Subscribers)

- **الهدف**: إقناع المستخدم بالاشتراك عبر توضيح القيمة والمحتوى والمدرب.
- **المكونات الأساسية**:
  - غلاف/عنوان + نبذة.
  - تقييمات (الدورة/المعلم) + عدد المراجعات.
  - أبرز ما ستتعلمه (Bullets).
  - معاينة وحدات/دروس (مقفل/Preview حسب السياسة).
  - زر أساسي: “اشترك الآن” + زر ثانوي: “مشاركة”.
  - زر مفضلة.
- **التفاعلات**:
  - “اشترك الآن” ⟵ يبدأ (الاشتراك في الفترة الخطوة الأولى).
  - “مشاركة” ⟵ يفتح (مشاركة الدورة).
  - “تسجيل الدخول” يظهر عند الحاجة (إن كانت الاشتراكات تتطلب حساباً).
- **الحالات**:
  - تحميل بيانات الدورة.
  - خطأ: فشل التحميل.
- **التحقق والقيود**:
  - إذا لم يكن المستخدم مسجلاً: يُطلب تسجيل الدخول قبل الدفع/الاشتراك (حسب القاعدة).
- **البيانات المطلوبة**:
  - `course` (id, title, description, outcomes[], rating, teacher, periods[])
  - `subscriber_state=false`
- **التتبع**: `course_view`, `subscription_start`, `share_course`.
- **معايير القبول**:
  - زر الاشتراك يعرض أسعار/فترات صحيحة قبل الانتقال للدفع.

## 6) 🔐 تسجيل الدخول (Login)

- **الهدف**: تمكين المستخدم من إنشاء جلسة آمنة للوصول للاشتراكات والمفضلة والمحتوى.
- **المكونات الأساسية**:
  - حقول: رقم جوال/بريد (حسب النظام) + كلمة مرور / رمز تحقق (OTP إن وجد).
  - زر “تسجيل الدخول”.
  - روابط: “نسيت كلمة المرور” (إن وجد) + “إنشاء حساب” (إن وجد).
- **التفاعلات**:
  - إدخال البيانات ثم تسجيل الدخول.
  - إظهار/إخفاء كلمة المرور (إن وجدت).
- **الحالات**:
  - تحميل أثناء المصادقة.
  - خطأ: بيانات غير صحيحة/محاولات كثيرة/انقطاع شبكة.
- **التحقق والقيود**:
  - صيغة البريد/الجوال صحيحة.
  - منع الإرسال إن كانت الحقول ناقصة.
- **البيانات المطلوبة**:
  - `identifier`, `password|otp`
  - مخرجات: `access_token`, `user_profile`
- **التتبع**: `login_attempt`, `login_success`, `login_failure` (مقترح).
- **معايير القبول**:
  - بعد نجاح الدخول يعود المستخدم إلى سياق رحلته (مثلاً: تفاصيل الدورة/الاشتراك).

## 7) 📤 مشاركة الدورة (Share Course)

- **الهدف**: تمكين المستخدم من مشاركة رابط الدورة لزيادة الانتشار العضوي.
- **المكونات الأساسية**:
  - معاينة: اسم الدورة + صورة مصغرة.
  - زر/إجراء مشاركة النظام (iOS/Android share sheet).
  - (اختياري) نسخ الرابط.
- **التفاعلات**:
  - اختيار قناة مشاركة (واتساب/تلغرام/…).
- **الحالات**:
  - تحميل رابط مشاركة ديناميكي (إن كان عبر خدمة Deep Links).
- **البيانات المطلوبة**:
  - `course_id` → `share_url`
- **التتبع**: `share_course` مع `channel`.
- **معايير القبول**:
  - الرابط يفتح التطبيق مباشرة إن كان مثبتًا، أو يفتح صفحة متجر (إن كانت Deep Link مفعلة).

## 8) 💳 الاشتراك في الفترة الخطوة الأولى (Period Subscription - Step 1)

- **الهدف**: اختيار فترة/باقة الاشتراك وتأكيد تفاصيلها قبل الدفع.
- **المكونات الأساسية**:
  - اسم الدورة + تفاصيل المعلم.
  - قائمة فترات (Cards): مدة + سعر + ميزات.
  - ملخص طلب: إجمالي + ضريبة (إن وجدت).
  - زر “التالي”.
- **التفاعلات**:
  - اختيار فترة واحدة.
  - التالي ⟵ إلى (الخطوة الثانية).
- **الحالات**:
  - تحميل الفترات.
  - خطأ فترات غير متاحة.
- **التحقق والقيود**:
  - لا يمكن المتابعة دون اختيار فترة.
- **البيانات المطلوبة**:
  - `periods[]`, `selected_period_id`
- **التتبع**: `subscription_start` (step=1).
- **معايير القبول**:
  - السعر النهائي مطابق للفترة المختارة.

## 9) 🧾 الاشتراك في الفترة الخطوة الثانية (Period Subscription - Step 2)

- **الهدف**: تنفيذ الدفع/تأكيد الاشتراك وإظهار النتيجة.
- **المكونات الأساسية**:
  - ملخص نهائي (الدورة/الفترة/السعر).
  - خيارات الدفع (حسب التكامل): بطاقة/Apple Pay/… .
  - زر “ادفع الآن”.
  - شاشة نجاح/فشل.
- **التفاعلات**:
  - تنفيذ الدفع ثم إنشاء اشتراك.
  - في النجاح: زر “ابدأ التعلم” ⟵ تفاصيل الدورة للمشتركين.
  - في الفشل: زر “إعادة المحاولة” + “تغيير طريقة الدفع”.
- **الحالات**:
  - Loading أثناء معالجة الدفع.
  - فشل بوابة الدفع/إلغاء المستخدم.
- **التحقق والقيود**:
  - منع الضغط المكرر (Debounce) على “ادفع الآن”.
- **البيانات المطلوبة**:
  - `payment_method`, `selected_period_id`
  - مخرجات: `order_id`, `subscription_status`
- **التتبع**: `subscription_success|failure`.
- **معايير القبول**:
  - بعد نجاح الدفع يصبح المستخدم “مشترك” فورًا وتُفتح المحتويات المقفلة.

## 10) ⭐ تقييم الدورة والمعلم (Rate Course & Teacher)

- **معايير القبول**:

## 📌 ملاحظات تنفيذية (للفريق التقني)
- اعتماد مصدر حقيقة واحد لحالة الاشتراك (Server-side) مع كاش محلي آمن.
- توحيد مكونات القوائم والبطاقات لتقليل التباين البصري وسرعة التطوير.

  - Pagination للنتائج/المنشورات/الرسائل
  - حالات `is_favorited`, `subscription_status`
  - روابط مشاركة ديناميكية (Deep Links) إن أمكن
